Connect Google

Sign in once so Job Tracker can save applications to your Google Sheets.

Job Tracker uses Google sign-in to write rows into your spreadsheets. Use the same Google account that can edit those sheets.

  1. Sign in with Google

    Sign in with the account that can edit your job tracker spreadsheet. Then open Settings and paste a sheet link that account can edit.

    Google is connected. Close this tab and add a sheet in Settings.

Advanced: use your own Google Cloud OAuth client

Optional for most people. Use this only if you want Job Tracker to use an OAuth client from your Google Cloud project (or if the publisher build has no baked-in credentials yet).

  1. Enable the Sheets API

    This lets your Google Cloud project talk to Google Sheets.

    Open Google Sheets API
    1. Sign in with the Google account that will own your job tracker spreadsheet (and can edit it).
    2. If Google asks you to create or choose a project, create one and name it something clear, like Job Tracker.
    3. On the Google Sheets API page, click Enable.
    4. When it finishes, return to this tab and continue.

  2. Choose who can sign in

    Google needs a short “who is allowed” setup before it will create a login key. For a personal Gmail account, this must be External.

    Open Audience settings
    1. Open Google Auth Platform → Audience (or OAuth consent screen, depending on Google’s layout).
    2. Set User type to External. Do not choose Internal unless every user is inside the same Google Workspace organisation.
    3. Fill in an app name (for example Job Tracker) and your email if Google asks for branding details.
    4. While Publishing status is Testing, click Add users and add the same email you will use to sign in. Save.

    External + Testing only allows people on your test-user list. It does not publish the app to the public.

  3. Create a Web application client

    Create the login key Google calls an OAuth client. Application type must be Web application — not Chrome extension or Chrome app.

    Open Credentials
    1. Click Create credentials → OAuth client ID.
    2. Application type: Web application.
    3. Name: anything helpful (Job Tracker is fine).
    4. Leave Authorized JavaScript origins empty. Do not add a URI in that section.
    5. Under Authorized redirect URIs (the second URI section), click + Add URI.
    6. Click Copy below, paste into that box, and keep the slash at the end. The link must match exactly.
    7. Click Create.

  4. Paste the Client ID and secret here

    Google shows two values after Create. Paste them below and save. They stay in this browser only.

    1. Copy Client ID — it usually ends with .apps.googleusercontent.com.
    2. Copy Client secret from the same client. If you closed the dialog, open the client again to find it.
    3. Click Save connection, then use Sign in with Google above.

Common problems and fixes

If something fails, match what you see below.

Access blocked / “can only be used within its organisation” (403 org_internal)

Cause: Audience / User type is set to Internal, which blocks personal Google accounts.

Fix:

  1. Open Audience.
  2. Change User type to External (Make external).
  3. Add your email as a test user if status is Testing.
  4. Wait about a minute, then sign in again. You do not need a new Client ID.
Error 400 / redirect request / redirect URI mismatch

Cause: The redirect link in Google does not exactly match the one Job Tracker uses.

Fix:

  1. Open Advanced above and copy the redirect URI.
  2. Open your OAuth client in Credentials.
  3. Paste it under Authorized redirect URIs only — not under Authorized JavaScript origins.
  4. Include the trailing slash. Save, wait a minute, then try again.
  5. Confirm Application type is Web application.
“This app hasn’t been verified” or Google shows a warning screen

Cause: New apps in Testing show a warning. That is normal for personal use.

Fix: Click Advanced, then continue to Job Tracker (or your app name). You do not need Google verification to use this yourself.

Sign-in works for someone else but not for you / “access denied”

Cause: While the app is in Testing, only listed test users can sign in.

Fix: On Audience, add the exact email address you are using, save, then try again.

Client secret / invalid client / could not exchange code

Cause: Client ID and Client secret are missing, mistyped, or from different clients.

Fix: Open Advanced, paste both values from the same OAuth client, click Save connection, then sign in.

Signed in, but Job Tracker can’t edit the spreadsheet

Cause: The signed-in Google account is not an editor on that sheet.

Fix: Open the spreadsheet in Google Sheets → Share → give that same account Editor access. Or sign out and sign in with an account that already can edit it.

Sign-in window closes with no clear message

Cause: The flow was cancelled, blocked by a Google error page, or the popup was closed early.

Fix: Try sign-in again. If Google showed an error first, use the matching problem above.

I already set this up and need to start over

Fix: You can reuse the same Google Cloud project. Update Audience or the redirect URI if needed, paste a new Client ID/secret under Advanced if you created a new client, Save connection, then sign in again.
